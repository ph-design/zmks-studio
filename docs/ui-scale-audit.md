# UI 缩放回归与布局审查

审查日期：2026-11-08。基于本地 `main` / `94e83f9`，工作开始时无已跟踪文件改动。

## 结论与历史证据

直接回归来自 `8773d4d`（2026-11-03）的像素样式 → Tailwind 工具类转换，并非 Tailwind 大版本升级。项目当前仍使用 Tailwind 3.4。

| 历史节点 | UI 变化及影响 |
| --- | --- |
| `c6a6235`，2026-07-21 | 引入 Carbon 外壳，根字号设为 14px。外壳主要使用显式 px，因此顶栏仍是 48px；rem 工具类与 px 控件已经存在不同基准。 |
| `f48647d`，2026-07-22 | 整合 Carbon，移除 container-queries 插件；并未修正根字号。 |
| `ea262b6`，2026-11-01 | 引入共享二级侧栏和编辑网格，侧栏宽度按断点为 224/192/160px。此版本用于迁移前实际渲染对照。 |
| `8773d4d`，2026-11-03 | 顶栏、面包屑、底栏以及共用控件改用 `h-12`、`h-10`、`h-8`、`text-sm`、`text-xs`；根字号仍为 14px，造成这些元素缩小至预期的 87.5%。 |
| 当前 `94e83f9` | 上述单位错配仍在。仍用内联 px 的二级侧栏、开关等没有同比缩小，导致视觉比例不统一。 |

具体转换：48px → `3rem` → 42px；14px → `0.875rem` → 12.25px。相同原因还影响边距、按钮宽高、字体与 rem 定义的图标尺寸。

迁移还包含有意的设计变化：主导航行高从 40px 改为 `h-12`，字号从 14px 改为 15px，图标从 16px 改为 18px，导航宽度从 220px 改为 `w-56`。这些不应被误判为同一个缩放错误，修复后保留其新设计值。

## 本次修复

- `src/index.css`：根字号 14px → 16px，明确 `body` 字号为 14px。恢复 Tailwind 工具类预期尺寸，同时保留默认正文密度和显式 px 控件尺寸。
- `src/carbon/CarbonChrome.tsx`：缩放控件的加减按钮保持 28px 宽；中间按钮恢复内容自适应宽度并禁止换行。迁移时复用 `w-7` 导致中文“自适应”换行，现已修复。
- 未修改功能数据流、硬件协议、依赖声明或锁文件。

## 首轮发现的布局／视觉问题（已于后续修复）

以下保留首轮审查证据。七项问题现已修复，具体实现与回归结果见 [布局与文案修复记录](ui-refinement.md)。

### 1. P1：浅色主题的主操作按钮文字不可读

连接页“连接 dongle”同时包含 `bg-transparent` 和 `bg-primary`，实际背景为透明，文字为白色，在白底上几乎不可见。共用 `secondaryButton` 也被确认动作复用，影响范围不只一个按钮。

- 位置：`src/carbon/CarbonChrome.tsx:281`、`:294`、`:335`。
- 实测：`color=rgb(255,255,255)`，`background-color=rgba(0,0,0,0)`。
- 建议：公共按钮只定义尺寸；背景颜色放到互斥的主／次／危险状态分支，避免同时生成相冲突的类。
- [截图](ui-scale-audit/primary-light.png)

### 2. P1：组合键页在默认桌面宽度下横向溢出

1280×760、主导航展开时，编辑区切成 8:4 双栏，右栏实测只有约 251px，而“超时”的标签、滑条、数值框合计占用约 329px。数值框伸出视口，页面出现横向滚动。断点按整个窗口判断，没有考虑两级侧栏已经占去的宽度。

- 位置：`src/index.css:478` 的网格断点、`src/combos/ComboPanel.tsx:468` 的固定最小标签宽度及滑条。
- 建议：依据内容容器可用宽度切换单双栏；滑条设 `min-width:0`，窄栏将标签放在上一行。
- [截图](ui-scale-audit/combos-1280.png)

### 3. P1：绑定编辑器在最小桌面窗口内无法正常显示 HID 内容

960×640、主导航展开时，绑定编辑器仅宽 544px，固定列为 `168px 200px 176px`。选择 Layer-Tap 后，第三列内部的修饰键栏又固定为 `w-44`（176px），HID 主区被压缩，中文分类出现逐字竖排，键码网格不可用。折叠主导航可以缓解，但不是可靠的布局适配。

- 位置：`src/behaviors/BehaviorBindingPicker.tsx:408`、`src/behaviors/HidUsageGrid.tsx:475`。
- 建议：小容器将分类／行为改为下拉或分步切换；修饰键移到底部或可折叠区域，不应同时保留多条固定宽度栏。
- [截图](ui-scale-audit/binding-960.png)

### 4. P2：灯光页“自适应”实际固定为 80%，预览裁切

`LightingView` 把模型的 `"auto"` 转换为 `0.8`，再传给画布及灯光预览。因此点击自适应仍回到 80%，而不是根据容器计算比例。1280px 和 960px 宽下都观察到模拟全尺寸键盘左右裁切；这与全局 rem 问题是两件事。

- 位置：`src/carbon/LightingView.tsx:55`、`:93`。
- 建议：把 `"auto"` 原样传递给 `PhysicalLayout`，使用现有 `fitContainerRef` 适配。
- [截图](ui-scale-audit/lighting-1280.png)

### 5. P2：拍一拍测试区的历史栏被压为零宽

960×640、主导航展开时，测试区三个子栏实测宽度为 170px、294px、0px。最新结果与计数占满宽度，历史区使用 `flex:1; min-width:0; overflow:hidden`，没有换行策略。空历史时不明显，有识别事件时也缺少可用显示空间。

- 位置：`src/carbon/MotionView.tsx:425`、`:431`、`:453`、`:473`。
- 建议：用容器断点将历史移到下一行；小窗口降低固定区域占高，保证下方设置仍有空间。

### 6. P2：手机宽度下二级侧栏和多列编辑器没有收拢机制

主导航在小屏变成覆盖层，但 `.carbon-feature-rail` 在 767px 以下仍固定占 160px。390px 浏览器只剩约 230px 给映射／灯光／体感／组合键主内容，多列控件的空间问题会进一步加重。

- 位置：`src/index.css:503` 以及上述绑定编辑器的固定列。
- 此项为共享布局的结构性限制；桌面客户端最小宽度为 960px，因此主要影响网页端。
- 建议：二级侧栏在小容器改为顶部选择器或可收起抽屉。

### 7. P3：手机宽度下语言选择器标签被截断

390px 宽时五种语言等分单行，每项约 73px；法语和西班牙语的文本加内边距超过分配宽度，显示省略号。此处是用户选择语言的入口，完整自称比统一等宽更重要。

- 位置：`src/carbon/PreferencesView.tsx:62`、`src/carbon/CarbonChrome.tsx:35`。
- 建议：窄屏使用 Select，或允许多行、按内容宽度排布。
- [截图](ui-scale-audit/preferences-390.png)
