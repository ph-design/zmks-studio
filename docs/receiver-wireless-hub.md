# 双键盘无线改键与 BLE 鼠标

配合实验 Hub 0.6.5，可同时连接两把电池供电的 EVO 和一只 BLE HID 鼠标。电脑只插 Hub，PC 蓝牙可以关闭。

选择“2.4G 接收器”后，先连接接收器管理接口，再从在线键盘列表选择配置对象。接收器连接和状态查询独立于键盘 Studio 会话；退出键盘配置后仍可管理接收器。Fn+反斜杠物理解锁所选 EVO。一次配置一把键盘，两把仍可同时输入。

本机 COM63 为管理接口（AT），COM62 为配置接口（Studio）；编号由系统分配，可能变化。Windows 桌面端依据 USB 接口标识 MI_00 / MI_02 区分用途，并通过父设备标识匹配同一接收器的两路接口。浏览器无法读取这些接口标识，会先显示用途提示；若误选已打开的管理接口，会在打开或发送 RPC 前拒绝连接。

第二槽位使用 230400 波特率并等待 `HUB_TARGET=1\r\n`，确认后才发 RPC；旧单键盘 Hub 因此不会误把第二键盘的操作送到第一把。第一槽位保持 115200 和旧二进制协议。网页和桌面连接均设置 DTR，取消 / 失败时释放串口。

接收器面板显示两个独立槽位的配对、链路、电量、频道与收包计数。首次加入槽位时，用 USB 连接并解锁对应键盘。先探测 `pairing.set_channel` 扩展，再生成独立密钥 / 地址并设置共用频道；旧键盘固件会在生成配对前被拒绝。管理会话打开时禁止修改 / 清除槽位。日志对配对命令中的密钥进行隐藏。

鼠标真正进入 BLE HID 配对模式后，点击“扫描鼠标”，从新扫描结果连接；不要在 PC 蓝牙弹窗连接。忘记鼠标不清除键盘配对。扫描和连接后限时刷新状态，避免异步操作完成后按钮仍显示旧状态。AT 队列同时等待命令回复与写入锁释放，再处理下一条命令。

RPC 15 秒未回复会终止该连接，结束等待并释放全局 RPC 队列。保存超时表示结果未知，应先重连检查；不会自动重试写闪存或丢弃现有改动。

2026-11-14：两把 EVO 电池供电，IN10 与其共存，用户确认三设备输入正常，最终鼠标未重启即可输入。两槽位无线查询返回不同身份；第二把既有 5 层配置在备份和明确授权后保存成功，读回一致，第一把未写入。

接收器断言定位、时隙规避和实机范围见固件配套 PR。最终版 20 次 AT 串口开关 / 60 次状态查询通过。前端 14 项测试 / 67 断言、生产构建及 Rust 编译检查通过；Rust 锁文件仅同步既有 manifest 的应用版本，不改依赖版本。

无线页面曾通过本机串口桥连接真实 Studio 接口；最终完整原生选择器、扫描 / 连接 UI 路径没有自动化端到端复测。管理查询耗时不等于按键延迟；长时间稳定性、其他鼠标和拥挤射频环境仍待验证。发布数据刷新返回 403 时构建沿用现有缓存。

## 配套源码

固件 PR 提供 `ph-design/ph_lite-zmk-config` 下的 `experimental/wireless-hub/` 独立应用及 `experimental/studio-2g4/` 固定基线补丁。第二键盘需要频道设置扩展；普通 ZMK 发行版不能假定支持。原始设备备份和个人键位不属于发布源码。

## Motion Guard 与接收器指示灯

Hub 0.6.7 的 `HUB_MOTION=槽位,READY|LOCKED|UNKNOWN` 独立解析到每把键盘。离线或未提供该字段时显示状态未知，不推断为已锁定。在线键盘全部锁定时深度呼吸，部分锁定时浅呼吸，没有锁定时使用正常连接指示。呼吸周期固定 2.4 秒；原有闪烁周期选项不控制呼吸周期。连接快速双闪，断开较慢双闪；设备识别和低电量警告具有优先级。

管理会话可见时每 1.5 秒查询一次状态；该轮询不经过键盘 RPC 串口。新版键盘状态明确识别 Motion Guard 后，运动页显示保护策略与基础开关，隐藏不适用的旧版休眠参数。策略数值为固件默认值说明，不伪装成可编辑或已读回的配置。

2026-11-15：18 项测试 / 85 个断言、TypeScript、生产构建及 Windows Rust 编译检查通过。浏览器使用双键盘串口模拟验证“先管理连接、后选择键盘 2”、230400 目标确认、持续管理会话及状态展示；不代表已完成原生桌面双串口实机端到端验证。

## 后台刷新与交互状态

后台 `queryStatus(true)` 保留 AT 队列的串行化和错误处理，但不占用用户操作的 `busy` 状态；手动刷新和写入仍显示忙碌、禁用相关操作。相同状态保留原引用，失败响应不以部分数据替换有效状态。浏览器延迟串口模拟连续三个后台查询周期中，按钮 / 滑块没有 disabled 属性变化。
